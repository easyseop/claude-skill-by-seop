## 질문 2 — 차단 B 미확인 사항: **해소 — (b)가 정답**

공식 문서 조사 결과(hooks 레퍼런스, code.claude.com/docs/en/hooks.md):

1. **파일 정의 없는 슬래시 명령은 Unknown command로 클라이언트에서 거부**되며 어떤 훅도 발화하지 않는다. 훅 matcher가 명령을 동적으로 "등록"하는 효과는 없다. → 현재 문구("사용자가 `/om-resume`을 새로 입력해 훅이 marker를 만들게 한다")는 성립하지 않음. **(a) 기각, (b) 채택.**
2. 사용자 수준(`~/.claude`)에도 om-resume 없음(실측).
3. 훅 발화 순서는 UserPromptExpansion(슬래시만) → UserPromptSubmit(모든 프롬프트, 확장된 프롬프트로).

### (b)의 구체 수정 방향 (검토자 보강)

- **marker 재생성의 실전 경로는 Skill 도구 호출이다**: `hook_cli.py:123-133`의 PreToolUse 분기가 `Skill(om-plan|om-resume)` 호출 시 **marker가 없으면 생성**한다. 스킬로 이식된 후에는 이 경로가 성립한다. → 7단계 문구를 "사용자가 `/om-plan`을 다시 호출한다(스킬 호출 시 훅이 세션 marker를 생성). 새 run을 만들지 말고 기존 RUN_DIR로 `plan-resume`를 실행한다"로 교체 권고.
- **om-resume 파일 신설은 별도 사람 결정**: settings matcher(`^(om-plan|om-resume)$`)와 hook_cli가 이미 그 이름을 전제하므로, 이식 시 얇은 om-resume 스킬을 추가하는 것이 설계 의도와 정합. 단 이번 저작 범위 밖 — 이식 결정 항목으로 기록.

### 부수 발견 2건 (검사기 후속 정비 목록행 — 이번 수정 범위 아님)

1. **훅 필드명 불일치 가능성**: 공식 문서의 UserPromptExpansion 입력 필드는 `slash_command_name`인데 `hook_cli.py:102`는 `command_name`을 읽는다. 불일치가 실제라면 Expansion 분기(우회 차단)는 항상 no-op(죽은 코드)다. **이식 후 실기동 스모크 테스트 1회를 이식 절차에 필수로 넣을 것.**
2. Submit 분기의 prefix 검사는 확장된 프롬프트를 받으므로(위 순서), 스킬 확장 후 프롬프트가 `/om-plan`으로 시작하지 않으면 Submit 경로 marker 생성은 동작하지 않을 수 있다 — 실전 경로가 PreToolUse(Skill)라는 위 판단을 뒷받침. 같은 스모크 테스트로 확인.
