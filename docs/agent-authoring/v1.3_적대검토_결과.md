# claude-skill-author v1.3 적대적 검토 결과 (설치 전 독립 검증)

검토일: 2026-09-02. 방법: 실제 scripts/*.py 코드 경로를 파일·줄 단위로 검증(문서 주장이 아니라 기계 강제 여부). 검토자: 독립 서브에이전트(읽기 전용).

## 3대 주장 판정

| 주장 | 판정 | 근거 |
|---|---|---|
| **G1** 원문(SOURCE_REQUEST) 잠금 | **강제됨(ENFORCED)** | init 시 sha256 잠금(init_authoring.py:150-152), resume 시 경로·내용 변경이면 exit 2(:245-250), 모든 phase에서 재해시 대조(validate_authoring.py:239-259). 잠금 후 수정하면 실제 차단. fail-closed. |
| **G2** 설계 독립 감사 인증 | **부분(PARTIAL)** | 인증서 존재·digest 결속은 강제(:441-471, 봉인 후 입력 변경 시 불일치로 차단). **그러나** 서명·독립성 증명 없음 — 인증서는 자기선언 문자열(`- 판정: PASS` 정규식), seal_attestation.py 스스로 "암호 서명 아님" 명시. 파이프라인 실행자 한 명이 혼자 유효 인증서 생성 가능. |
| **G3** 설계 선완성 게이트 | **강제됨(ENFORCED)** | spec은 design PASS 없으면 exit 1(validate_prior_phases:697-711), design fingerprint 실시간 재계산으로 STALE 차단(:704-710). 20섹션·18요구는 실제 개수 검사(:32-39, :25-31), digest 검증 실재. fail-closed. |

## 팀 배포 전 알아야 할 잔여 한계

1. **인증서는 위조 가능·독립성 미증명** (G2 핵심). "작성자≠감사자" 분리는 코드가 아니라 절차 관행. 인증서를 "제3자 서명"으로 신뢰하면 안 됨 — 신선도(stale 재사용 방지) 게이트로만 신뢰.
2. **감사 보고서 본문은 판정 한 줄만 검사** — 커버리지·감사자 신원·지적 목록 미검증(:225-236).
3. **설계 요구 출처는 존재 미검증** — 인용 문자열이 채워지기만 하면 통과(:515-517). (단 intake 쪽 출처는 실제 파일 앵커 검증됨.)
4. **REQ-### 추적은 원문→설계까지만**, 설계→명세(COMMAND_SPEC) 연결은 ID 단위로 검증 안 됨.
5. **런타임 하드 차단은 선택적 Stop 훅 의존** — 미설치 시 런타임에서 파일 쓰기를 막는 것은 없고, 증거만 FAILED로 남음.
6. TODO/stub 없음, 표준 라이브러리만 사용, 스크립트 완성 상태.

## 종합

세 주장이 문서가 아니라 실제 결정적 코드로 뒷받침됨 — G1·G3는 진짜 기계 강제·fail-closed로, 순수 문서형 하네스보다 확실히 우수. G2만 마케팅이 기계를 앞섬(신선도 게이트는 확실하나 위조 방지·독립성 증명은 없음). **팀 배포에 "완전성+신선도 게이트"로는 production 사용 가능**하되, 인증서를 변조 불가·제3자 서명으로 취급하면 안 됨. → 개선 후보: 인증서 서명화, 감사 보고서 본문 검사 강화, 설계→명세 REQ 추적, Stop 훅 기본 배선.
