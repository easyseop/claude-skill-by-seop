# claude-skill-author v1.4 개발 요청 (코덱스) — v1.3 적대검토에서 나온 개선 항목

작성일: 2026-09-02. 근거: `docs/agent-authoring/v1.3_적대검토_결과.md`(독립 코드 검토). v1.3는 G1·G3 기계강제 확인, G2 부분. 아래는 잔여 한계를 게이트로 승격하는 요청. 각 항목에 반례 테스트 필수, 제품/사용자 코드 무수정 원칙 유지.

## 우선순위 1 — G2 인증서 위조·독립성 (가장 중요)

**문제**: 설계·최종 감사 인증서(DESIGN_AUDIT_ATTESTATION·AUDIT_ATTESTATION)가 봉인 후 변경은 digest로 잡지만, **서명이 없어 파이프라인 실행자 한 명이 혼자 유효 '판정: PASS' 인증서를 생성 가능**. "작성자≠감사자" 분리가 코드가 아니라 절차 관행(seal_attestation.py:2-6이 "암호 서명 아님" 명시, validate_authoring.py:455·229-234는 문자열 정규식만).
**요청**: ① 감사자 실행 컨텍스트를 인증서에 결속(예: 감사 서브에이전트만 접근 가능한 토큰/키로 서명, 또는 감사 실행 로그의 독립 digest를 인증서에 필수 포함). ② 작성 단계와 감사 단계가 같은 산출물을 만들 수 없도록 역할 분리를 기계로 강제. 최소선: 인증서에 "누가·어떤 실행에서 감사했는가"의 위조 어려운 증거를 결속하고, validate가 그 증거를 검증.
**반례**: 작성자가 손으로 만든 인증서 → 차단 / 감사 산출물 없이 PASS 문자열만 → 차단(현행 유지) / 정상 감사 실행 산출 → 통과.

## 우선순위 2 — 감사 보고서 본문 검증 강화

**문제**: audit_verdict(:225-236)가 `- 판정: PASS` 한 줄만 있으면 수용. 커버리지·감사자 신원·지적 목록 미검증.
**요청**: 감사 보고서에 필수 섹션(확인 범위, 발견 목록 또는 "발견 0" 근거, 감사자 역할) 강제. 빈 통과 보고서 차단.

## 우선순위 3 — 설계 요구 출처 존재 검증

**문제**: validate_authoring.py:515-517이 설계 요구의 `sources`를 문자열 채움만 검사 — 날조 인용 통과. (intake 쪽 출처는 이미 파일 앵커 검증됨 — source_anchor_exists:313-329.)
**요청**: 설계 요구 출처도 intake와 동일하게 실제 파일·앵커 존재 검증으로 통일.

## 우선순위 4 — REQ-### 추적을 설계→명세까지 연장

**문제**: REQ-### 원자 추적이 원문→설계까지만(design_links를 DESIGN.md 텍스트에서 확인). 설계→COMMAND_SPEC은 ID 단위 연결 미검증(purpose/user_outcome 문자열 일치만).
**요청**: 각 REQ-###가 COMMAND_SPEC의 어느 항목으로 이어지는지 ID 단위 추적·검증.

## 우선순위 5 — Stop 훅 기본 배선 안내 강화(선택)

**문제**: 런타임 하드 차단이 선택적 Stop 훅에만 의존, 미설치 시 런타임 방어 없음(증거만 FAILED).
**요청**: 필수는 아니나, 설치 시 Stop 훅 배선을 강하게 권고하는 안내 + 미배선 시 위험을 install 보고에 명시.
