# 자연어 요구사항 도출·질문 규칙

## 목적

사용자가 “이 행동을 통제하는 스킬을 만들고 싶다”처럼 최소한의 자연어만 제공해도, 원문을 보존하고 불필요한 질문을 반복하지 않으며 감사 가능한 설계 입력으로 변환한다.

## 원천 파일 분리

- `SOURCE_REQUEST.md`: 최초 사용자 자연어의 불변 원형. 생성 후 수정하지 않는다.
- `SOURCE_DECISIONS.md`: 후속 질문에 대한 사용자 답변과 변경 결정. 시간순으로 추가한다.
- `REQUIREMENT_INTAKE.yaml`: 원문·결정·저장소 사실을 원자 요구사항으로 구조화한다.
- `DESIGN.md`: 승인된 요구사항을 실행 가능한 설계로 확장한다.

## 요구사항 유형

1. `USER_EXPLICIT`: 최초 원문에 사용자가 직접 명시한 요구
2. `USER_DECISION`: 후속 질문에서 사용자가 결정한 요구
3. `REPOSITORY_FACT`: 저장소 파일·테스트·규칙에서 확인한 사실
4. `SAFE_DEFAULT`: 저위험·가역 기본값이며 이유를 기록한 항목
5. `PROPOSAL`: 사용자 승인이 필요한 제안
6. `NON_BLOCKING_UNCERTAINTY`: 결과에 표시하면 진행 가능한 미확인 항목

각 요구사항은 `REQ-###` ID, 본문, 상태, 차단 여부, 근거, DESIGN 반영 위치를 가진다.

## 누락 항목 분류

- `USER_DECISION`: 사용자만 결정 가능하며 권한·운영 부작용·승인·완료 판정에 영향을 준다.
- `REPOSITORY_RESEARCH`: 저장소 조사로 해결한다. 사용자에게 묻지 않는다.
- `SAFE_DEFAULT`: 실패 비용이 낮고 되돌리기 쉬운 기본값을 적용한다.
- `NON_BLOCKING_UNCERTAINTY`: 미확인으로 남겨도 설계 진행이 가능하다.

## 질문 게이트

1. 사용자가 이미 답한 내용을 다시 묻지 않는다.
2. `REPOSITORY_RESEARCH`는 먼저 직접 조사한다.
3. `SAFE_DEFAULT`는 이유와 영향 범위를 기록한다.
4. 차단되는 `USER_DECISION`만 한 번에 묶어 질문한다.
5. 질문은 3~5개를 권장 상한으로 하고 선택지·권장 기본값·영향을 제시한다.
6. 고위험 행동의 대상·권한·승인·복구 조건은 추측하지 않는다.
7. 답변은 `SOURCE_DECISIONS.md`, `REQUIREMENT_INTAKE.yaml`, `DESIGN.md`에 추적한다.
8. 차단 질문이 해결되지 않으면 intake와 design 상태를 `DRAFT`로 유지한다.

## 안전한 기본값

- 출력 경로 미지정: 대화 보고, 파일 쓰기 없음
- 수정 범위 불명확: 읽기 전용
- 테스트 명령 불명확: 저장소 공식 명령 조사, 없으면 미검증 보고
- 근거 부재: 사실 단정 금지, 미확인 표시

안전한 기본값으로 처리하지 않는 항목:

- 운영 DB 쓰기
- 배포
- 파일 삭제
- 외부 전송
- 비밀정보 접근
- 비용 발생 호출
- 보안·권한 완화

## Agent.md 필요성 판정

다음 중 하나 이상이 실질적으로 필요할 때만 대상 업무용 Agent.md를 만든다.

- 반복 호출되는 독립 전문 역할
- 메인 세션과 다른 도구·권한 경계
- 별도 컨텍스트 격리
- 장기 상태 또는 전문 메모리
- 다른 에이전트와 협업·인계
- 특정 Agent에서 `context: fork` 실행 필요

단순 `/스킬명` 호출로 충분하면 Agent.md를 만들지 않는다.
