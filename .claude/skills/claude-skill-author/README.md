# claude-skill-author — 통제형 스킬 제작 하네스 (v1.3)

## 무엇에 쓰는가

**"AI의 행동을 통제·게이트하는 스킬"을 자동으로 만들어 주는 스킬**이다. 자연어로 "이걸 못 하게 막고, 저 근거를 강제하고, 이 조건에서만 통과시켜라"를 말하면 → 원문 보존 → 설계 → 독립 감사 → 명세 → SKILL.md 작성 → 최종 감사 → 완료 게이트 순서로 검증 가능한 스킬을 산출한다.

**이럴 때 쓴다**: 코드 리뷰가 파일을 못 고치게, 모든 지적에 파일·줄 근거를 강제, 테스트 못 돌렸으면 통과 표시 금지 — 같은 **규칙·게이트가 핵심인 스킬**.
**이럴 땐 안 쓴다**: 번역·요약·정리 같은 단순 작업 스킬. 원문 잠금·설계 감사 같은 무거운 공정이 오히려 부담이다.

## 환경 요구사항

- **Python 3.11 이상** (스크립트가 `datetime.UTC` 등 3.11+ 기능 사용 — 3.9에서 즉시 실패)
- Claude Code (스킬·서브에이전트·훅 지원 버전)
- 표준 라이브러리만 사용 — 외부 패키지·네트워크 불필요
- 설치·실행 모두 로컬에서 완결. 네트워크 호출·Git 쓰기·제품 코드 수정 없음

## 설치

이 저장소에는 이미 `.claude/skills/claude-skill-author/`로 설치돼 있다. **다른 저장소에 설치**하려면 배포 zip의 `install.sh`를 쓴다.

```bash
# 대상 저장소 루트에서
./install.sh .              # 현재 저장소에 설치
./install.sh /path/to/repo  # 특정 저장소에 설치
```

- 설치 범위는 대상의 `.claude/` 하위뿐. 기존 파일은 `.bak-<UTC시각>`으로 백업한다.
- `.claude/settings.json`은 건드리지 않는다. Stop 훅은 예시 파일로만 깔린다(아래 참고).
- 설치 확인: `python3 tests/run_tests.py` (배포 zip 안에서) → `All ... tests passed`.

## 사용법

### 자연어 한 번으로 전체 생성

```text
/claude-skill-author evidence-code-review --mode full --agent auto

코드 리뷰 중 파일을 직접 수정하지 못하게 하고 싶다.
모든 지적에는 파일·줄 번호·코드 근거가 있어야 한다.
로컬 테스트 실행은 허용하되, 실행하지 못한 검사는 통과로 표시하지 않는다.
커밋과 푸시는 금지한다.
```

설계서가 없으면 `docs/skill-designs/<스킬명>/DESIGN.md`에 만들고, 작성 증거는 `.claude/skill-authoring/<스킬명>/`에 쌓인다.

### 모드 (단계별 실행)

| 모드 | 하는 일 |
|---|---|
| `design` | 원문 보존 · 요구사항 정리 · 설계 · 설계 독립 감사까지 |
| `spec` | design 통과 후 규칙 전수 판정 · 명세 확정 |
| `build` | 승인된 명세로 SKILL.md 등 런타임 파일 작성 |
| `audit` | 최종 읽기 전용 감사 |
| `full` | 위 전체 (기본값) |

### Agent.md 정책

`--agent auto`(기본, 필요시 생성) / `required`(항상) / `forbidden`(안 만듦).

### 선택적 Stop 훅 (권장)

`.claude/settings.stop-hook.example.json`의 `hooks.Stop` 부분을 **수동 검토 후** 기존 설정에 병합하면, 작업 종료 시 검증을 자동 재실행해 "통과 안 했는데 끝내기"를 런타임에서 막는다. **자동 병합하지 않으므로 직접 켜야 한다.**

## ⚠️ 무엇을 만들어 주고, 무엇은 안 만드는가 (오해 방지 — 필독)

이 하네스가 산출하는 것은 **`SKILL.md`(+ 필요시 `Agent.md`) 마크다운뿐**이다. 대상 스킬을 실제로 강제하는 **런타임 검사기(하드 차단 엔진·훅·권한 배선)는 만들어 주지 않는다.**

강제에는 두 층이 있고, 이 하네스는 아래쪽만 담당한다.

| 층 | 무엇을 강제하나 | 누가 만드나 |
|---|---|---|
| **대상 스킬 런타임 검사기** (예: 결정적 게이트·훅·CI) | "그 스킬이 실제로 규칙을 지키는가"를 기계로 차단 | **자동 생성 안 됨 — 별도 개발 필요** |
| **이 하네스의 자체 게이트** (validate_authoring.py) | "SKILL.md가 근거 있게·빈틈없이 만들어졌는가" | 하네스에 내장 |

즉, 생성된 SKILL.md의 규칙은 기본적으로 **AI가 읽고 따르는 지침(행동 유도)**이지, 어기면 프로그램이 막는 하드 차단이 아니다.

**그래서 잘 만들어진 통제 스킬의 조건은 이렇다:**

1. **강제할 검사기가 이미 구체적으로 구현돼 있을 것.** SKILL.md는 그 검사기의 실제 CLI·exit 코드·스키마를 **실측으로 받아적는 정확한 사용설명서** 역할을 할 때 가장 강력하다.
2. 검사기가 없다면, SKILL.md는 "잘 쓰인 지침서"까지가 한계다. 진짜 하드 차단이 필요하면 **검사기부터 별도로 개발**(예: 결정적 게이트 스크립트 + 훅 + 권한 배선)한 뒤 SKILL.md로 엮어야 한다.

> 이 하네스에 저작을 맡길 때, 검사기가 있으면 그 저장소·CLI·스키마 경로를 입력으로 함께 주면 SKILL.md가 정확히 결속된다. 없으면 먼저 검사기 개발을 계획할 것.

## 어떻게 신뢰를 담보하나 (v1.3 게이트)

```
최초 자연어 원문 잠금(수정 금지) → 요구사항 원자 추적 → 설계 20섹션·18요구 검사
→ 독립 설계 감사 → design 통과 전 spec 차단 → 명세 → 작성 → 독립 최종 감사 → 완료
```
이전 통과 후 원문·설계·명세가 바뀌면 뒤 단계가 자동으로 무효(STALE)가 되어 재검증을 요구한다.

## 알려진 한계 (배포 전 필독)

독립 적대 검토([상세](../../../docs/agent-authoring/v1.3_적대검토_결과.md)) 결과:

- ✅ **원문 잠금·설계 선완성 게이트는 진짜 코드로 강제**(fail-closed). 순수 문서형 하네스보다 확실히 우수.
- ⚠️ **감사 인증서는 "몰래 못 바꾸게"는 하지만 "제3자가 검수했다"는 증명은 아니다.** 파이프라인 실행자 한 명이 혼자 합격 인증서를 만들 수 있으므로, **인증서를 독립 검수 증명으로 신뢰하지 말 것** — 실제 독립 검수는 사람이 챙긴다. (개선 예정: [v1.4 요청서](../../../docs/agent-authoring/v1.4_개발요청_코덱스.md))
