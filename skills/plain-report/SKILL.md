# Plain Report — 기술용어 + "즉, ~입니다" 의역 병기

## 규칙
1. **기술용어는 그대로 유지**한다(정확성). 축약·생략하지 않는다.
2. 각 핵심 문장/표항목 **바로 뒤에 `> 즉, (일상어로 무슨 뜻·무슨 상황인지)입니다`** 한 줄을 붙인다.
3. 의역은 **비개발자도 상황을 파악**할 수 있게: "무엇을/왜/그래서 지금 어떤 상태"인지.
4. 통과/실패/보류를 **✅ / ⚠️ / ⏳** 등으로 시각 구분한다.
5. 마지막에 **"한 줄 요약"** 과 **"다음에 고를 수 있는 작업"**(각 항목도 `→ 즉, ...`)을 둔다.
6. 추측 금지 — 확인된 사실만. 모르면 "확인 필요"로 표시하고 의역도 그 사실대로.

## 형식 틀
```
# <제목>
**<목표/맥락>**
> 즉, <일상어 한 줄>입니다.

## ✅ 통과한 것
1. **<기술 사실>**
   > 즉, <일상어 뜻>입니다.

## ⚠️ 주의 / 미결
5. **<기술 사실>**
   > 즉, <일상어 뜻>입니다.

## 다음에 고를 수 있는 작업
1. <작업> → 즉, <효과>.

> 한 줄 요약: <전체를 한 문장으로>.
```

## 예시
- 기술: "1.13.1 데이터를 1.13.2가 마이그레이션하며 기동 → exit 0."
  > 즉, 기존에 쓰던 데이터를 새 버전이 문제없이 넘겨받아 켜졌습니다.
- 기술: "sybase 계약이 실패했으나 코드가 *PureUtils.ts로 relocation되어 생존, 앵커 stale."
  > 즉, 그 코드는 다른 파일로 이사만 갔고 기능은 살아있는데, 검사기가 옛 위치만 봐서 '없다'고 오판한 것입니다.
