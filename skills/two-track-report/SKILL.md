# Two-Track Report — 사람에게는 보고, 에이전트에게는 파일

## 원칙

**같은 내용을 두 번 쓰되, 받는 쪽에 맞게 다르게 쓴다.**

| 트랙 | 대상 | 형태 | 목적 |
|---|---|---|---|
| ① 보고 | 사용자(비개발자 전제) | 대화 메시지 | 상황 파악과 의사결정 |
| ② 상세 | 협업 에이전트·후속 작업자 | 저장소 안 파일 | 그대로 실행 가능한 지시·근거 |

사용자가 기술 상세를 이해해야만 다음 결정을 내릴 수 있는 구조로 만들지 않는다. **결정에 필요한 것은 ①에 다 있고, 실행에 필요한 것은 ②에 다 있어야 한다.**

## ① 사용자 보고 규칙

1. **문서를 하나도 안 읽은 사람**을 기준으로 쓴다. 직전 대화에서 설명한 용어도 다시 풀어 쓴다.
2. 순서: **무엇을 했나(한 줄) → 결론 → 문제·핵심(비유 허용) → 다음 행동**.
3. 기술용어는 쓰되 바로 뒤에 `> 즉, ~입니다` 형태의 의역을 붙인다(plain-report 방식). 의역 없이 3문장 이상 기술용어가 이어지면 실패다.
4. 비유는 **정확할 때만** 쓴다. 예: "감시 스위치를 감시 대상이 쥐고 있다", "성적표를 학생이 고칠 수 있는데 원본 대조를 안 한다". 정확한 비유가 없으면 비유 없이 평이하게 쓴다.
5. 세부 항목은 개수와 무게만 전달한다. 예: "덜 심각한 문제 16건 — 전부 파일에 정리".
6. 마지막에 **② 파일의 경로**를 알려준다. 사용자는 그 경로만 전달하면 된다.

## ② 에이전트 파일 규칙

1. 수신 에이전트가 **추가 질문 없이 실행**할 수 있는 수준으로 쓴다: 근거 파일·위치, 재현 방법, 구체적 수정안(파일 경로·예시 값 포함).
2. **사용자와의 대화에서 나온 결정·해명은 파일에 소급 반영한다.** 대화에만 남은 결정은 전달되지 않은 것이다.
3. 파일은 저장소 안에 두고, 사용자에게는 경로 하나로 전달 가능하게 한다.
4. ①에서 비유로 말한 것은 ②에서 기술 용어로 정확히 다시 쓴다. 비유를 파일에 넣지 않는다.

## 되묻기 신호 처리

사용자가 보고 속 용어를 하나하나 되묻기 시작하면("~가 뭐야?", "그게 수정 말하는 거야?") 그것은 ①이 너무 기술적이었다는 신호다.

1. 되물은 항목을 평이하게 다시 설명하고,
2. 그 설명에서 새로 구체화된 내용(메커니즘·예시·결정)은 **② 파일에 반영**한 뒤,
3. 이후 보고부터 같은 수준의 용어를 다시 쓰지 않는다.

## 하지 말 것

- 사용자 보고에 파일 내용을 통째로 붙여넣지 않는다(경로로 대신한다).
- "자세한 건 파일 참조"로 결론·문제 설명을 생략하지 않는다 — 결정 재료는 보고 안에 있어야 한다.
- 에이전트 파일에 대화체·비유·미확정 추측을 넣지 않는다.
